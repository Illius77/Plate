# Nutrition Tracker — план проекта

## Что это

Персональное PWA-приложение для трекинга питания с AI-нутрициологом.
Работает как сайт, добавляется на главный экран iPhone как обычное приложение.

---

## Стек

- **Frontend:** HTML + CSS + Vanilla JS (один файл index.html)
- **База данных:** IndexedDB в браузере (данные хранятся локально на телефоне)
- **Штрихкоды:** Open Food Facts API (бесплатно, Европа, без регистрации)
- **AI:** Google Gemini API — модель `gemini-2.5-flash-lite` (почти бесплатно)
- **Хостинг:** GitHub Pages (бесплатно)

---

## Структура проекта

```
nutrition-app/
├── index.html        # всё приложение (HTML + CSS + JS)
├── manifest.json     # делает сайт PWA (иконка на экране iPhone)
├── sw.js             # service worker для PWA
├── .env              # API ключ (не в репо! добавлен в .gitignore)
├── .env.example      # пример .env без реального ключа (в репо)
├── .gitignore        # игнорирует .env
└── PLAN.md           # этот файл
```

---

## Важно: API ключ

Ключ получен на aistudio.google.com (Google AI Studio).
Хранится в файле `.env`:

```
GEMINI_API_KEY=AIzaSy...твой_ключ
```

`.env` добавлен в `.gitignore` — никогда не попадает в репо.

Так как приложение статическое (GitHub Pages), ключ вписывается
прямо в JS при деплое. Для личного приватного репо это приемлемо.

## Почему Gemini 2.5 Flash-Lite

- Самая дешёвая стабильная модель: $0.10 вход / $0.40 выход за млн токенов
- Бесплатный тир: 1500 запросов в день бесплатно
- Для задачи "посмотреть на список продуктов и дать совет" — более чем достаточно
- Ожидаемая стоимость при реальном использовании: ~$0.05 в месяц

## База данных (IndexedDB на телефоне)

Две таблицы:

### 1. `meals` — лог приёмов пищи
```
id, date (YYYY-MM-DD), meal_type (breakfast/lunch/dinner/snack),
product_name, grams, kcal, protein, carbs, fat, timestamp
```

### 2. `products` — личная база продуктов
```
barcode, name, brand,
kcal_per_100, protein_per_100, carbs_per_100, fat_per_100,
last_used, use_count
```

Данные живут в Safari на iPhone.
Не теряются при обновлении кода на GitHub.
Теряются только если очистить данные Safari вручную.
Защита: кнопка "Экспорт в JSON" — раз в неделю сохраняешь бэкап.

## Экраны приложения

### 1. Дневник (главный экран)
- Дата + кнопка календаря (разворачивается сверху)
- Карточка: большие калории / осталось / прогресс-бар
- Макросы: Жиры / Углев / Белок с цветными барами
- Секции: Завтрак / Обед / Ужин / Перекус (сворачиваются по клику)
- Каждый продукт: "Название 100г" + ккал справа + ж/у/б снизу крупно

### 2. Поиск
- Строка поиска по названию
- Табы: Еда / Недавние
- Список → тап открывает карточку добавления

### 3. Карточка добавления продукта (bottom sheet снизу)
- Название + бренд
- Поле граммов с кнопками −/+
- Выбор приёма: Завтрак / Обед / Ужин / Перекус
- Макросы пересчитываются в реальном времени по граммам
- Кнопка "Сохранить" → продукт в дневнике, цифры обновляются

### 4. Сканер
- Открывает камеру через библиотеку html5-qrcode
- При скане штрихкода → ищет в Open Food Facts API
- Если нашёл → открывает карточку добавления с заполненными данными
- Если не нашёл → форма ручного добавления нового продукта в базу

### 5. AI нутрициолог (подключаем на шаге 7)
- Кнопка "Спросить AI" или авто после сохранения приёма
- Показывает анализ дня + чипы-рекомендации из арсенала
- Поле для вопроса

---

## Логика AI запроса (реализуем на шаге 7)

### Модель
```
gemini-2.5-flash-lite
```

### Endpoint
```
https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-lite:generateContent?key=ТВОЙ_КЛЮЧ
```

### Контекст запроса (~400 токенов)
```
[Цели на день]
2000 ккал, 150г белка, 70г жиров, 220г углеводов

[Сегодня уже съел]
Завтрак: овсянка 200г (340 ккал, ж7 у70 б12)
Итого: 340 ккал, ж7 у70 б12

[Арсенал — продукты за 30 дней, исключая сегодняшние]
творог, куриная грудка, яйца, гречка, рис, йогурт Emmi...

[Задача]
Оцени питание. Порекомендуй 2-3 продукта из арсенала
чтобы закрыть цели. НЕ предлагай то что уже съедено сегодня.
Отвечай коротко, по-русски, конкретно.
```

### Как формируется арсенал
- Берём все уникальные продукты из таблицы meals за последние 30 дней
- Исключаем те, что уже есть в записях сегодняшнего дня
- Передаём только названия — экономим токены

## Порядок разработки

### Шаг 1 — Структура файлов
Создать: index.html, manifest.json, sw.js, .gitignore, .env.example

### Шаг 2 — Верстка (статичная)
Главный экран с хардкод-данными. Все 4 экрана, навигация.
Без базы, без API — просто HTML/CSS.

### Шаг 3 — IndexedDB
Подключить базу. Сохранение и загрузка приёмов пищи.
Цифры на главном экране считаются из реальных данных.

### Шаг 4 — Поиск + карточка добавления
Поиск по своей базе продуктов. Bottom sheet с граммами.
Добавление в нужный приём пищи.

### Шаг 5 — Open Food Facts API
Поиск продукта по названию через API.
Автозаполнение КБЖУ из результата.
Возможность поправить цифры перед сохранением.

### Шаг 6 — Сканер штрихкода
Подключить html5-qrcode.
Скан → запрос в Open Food Facts → карточка добавления.
Если не нашли → форма ручного добавления.

### Шаг 7 — AI нутрициолог
Подключить Gemini API (gemini-2.5-flash-lite).
Формировать контекст из IndexedDB.
Показывать ответ + чипы-рекомендации.

### Шаг 8 — PWA
manifest.json + service worker.
Тест: добавить на главный экран iPhone через Safari.

### Шаг 9 — Деплой
Запушить на GitHub → включить GitHub Pages.
Открыть на iPhone, добавить на экран.

## Локальный запуск для разработки

```bash
python3 -m http.server 8080
# открыть: http://localhost:8080
```

Тест на iPhone — та же Wi-Fi, открыть http://[IP-мака]:8080 в Safari.
IP мака: Системные настройки → Wi-Fi → Подробнее.
